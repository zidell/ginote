# Ginote

## アプリ紹介

Ginote は、GitHub の Issues を個人用ノートのように使える、シンプルで安全な Web アプリです。
私は GitHub Issues が好きなのですが、動作がもたつき UX が使いにくい点にいつも不満を
感じていました。そこで、機能はほぼそのままに、使い心地だけをノートアプリのようにした
SPA アプリを作りました。このアプリは静的な JS だけで構成されており、ブラウザから
GitHub API と直接通信するので安全です。

サービス URL（誰でもすぐに利用できます）：[https://note.gitools.net](https://note.gitools.net)

## 主な特徴

- **プライベートリポジトリに直接保存：** 専用のアプリサーバーやデータベースを使わず、
  プライベート（Private）リポジトリの Issue をノートとして使います。
- **ブラウザから直接接続：** ブラウザが GitHub API を直接呼び出します。アプリ運営者の
  サーバーがノートや PAT を受け取って保管するような中間ステップはありません。
- **タグ・検索・ゴミ箱：** GitHub のラベルをタグとして使い（タグごとに分類の説明も
  付けられます）、本文検索とクローズ済み Issue を利用したゴミ箱に対応しています。
  よく見るノートは上部に固定できます。
- **コメント：** Issue のコメントを、ノートに追記する記録として使います。コメントにも
  ファイルを添付したり、音声で内容を残したりできます。
- **ファイル・画像の添付：** 本文とコメントの添付ファイルは同じリポジトリに保存され、
  アプリと GitHub の両方で確認できます。詳しくは
  [添付ファイルの保存方式](docs/ATTACHMENTS.md)を参照してください。
- **音声録音・文字起こし・整形（OpenAI のみ）：** ブラウザで録音した音声を OpenAI で
  直接文字起こしし、自然な文章に整形できます。整形の際にタイトルを生成したり既存タグを
  提案させたりでき、必要に応じて元の音声もノートの添付ファイルとして残せます。音声機能は
  現在 OpenAI API のみに対応しています。
- **ノートのロック（本文の追加暗号化）：** プライベートリポジトリへの保存だけでは不十分な
  場合、6 桁の数字でノートをロックし、本文とコメントをブラウザ上で AES-GCM によって
  さらに暗号化できます。詳しくは[暗号化方式](docs/ENCRYPTION.md)を参照してください。
- **編集ツール：** 複数のノートを 1 つに統合したり、本文を検索・置換（正規表現対応）
  したり、Markdown ビューアで表示結果を確認したりできます。
- **複数リポジトリの切り替え：** 複数のリポジトリを登録しておき、一覧や数字キーで
  すぐに切り替えられます。
- **キーボード操作：** ノート一覧の移動・オープン・選択、新規ノート作成、リポジトリの
  切り替えなどをキーボードで行えます。
- **MCP 連携：** GitHub 公式の MCP Server をつなぐと、AI ツールからも同じノート（Issue）
  を読み書きできます。アプリ専用の MCP サーバーは不要です。
- **Web とデスクトップに対応：** インストール可能な PWA と、Tauri ベースの macOS・
  Windows・Linux アプリを提供しています。デスクトップアプリのパッケージングとリリースは
  [デスクトップアプリのドキュメント](docs/DESKTOP.md)を参照してください。

## 使い方

### 自分のデータはどこへ行くの？

**Ginote はファイルとして配信される静的 Web アプリです。** 配信サーバーは HTML、CSS、
JavaScript などのアプリファイルを届けるだけです。ログインやノート保存を処理するアプリ
バックエンドはなく、アプリを開いた後のデータ通信はユーザーのブラウザと GitHub API の
間で直接行われます。

```text
ユーザーのブラウザ  ←──── 直接通信 ────→  GitHub
     │
     └─ PAT・アプリ設定・保存前の下書きはこのブラウザにのみ保管
```

- ノート、タグ、添付ファイルはユーザーが指定した GitHub リポジトリにのみ保存されます。
- PAT とアプリ設定はユーザーのブラウザにのみ保管され、認証時にのみ GitHub API へ送られます。
- 保存前の下書きはそのブラウザ内にのみ残ります。
- オプションのノート暗号化については[暗号化方式](docs/ENCRYPTION.md)にまとめています。
- アプリ運営者にノート、PAT、設定を送る API はなく、分析・トラッキングサービスも使って
  いません。

つまり、アプリファイルをダウンロードするリクエスト以外に、ユーザーのデータが GitHub 以外の
アプリ運営者や他のサーバーへ送られることはありません。ノートデータが実際に存在するのは
**自分のブラウザと、自分が選んだ GitHub リポジトリだけ**です。

### 音声録音を使う

音声録音を初めて使う前に、OpenAI の API キーが必要です。OpenAI で API キーを発行し、
Ginote の **設定 → 音声録音 → OpenAI API キー** に入力してください。API の使用量に
応じて OpenAI の料金が発生する場合があります。

設定が済んだら、サイドバーまたはノート画面のマイクボタンで録音を開始できます。録音を
終えると音声を文字起こしし、任意の整形モデルと整形ルールを適用して、本文・タイトル・
既存タグを提案します。設定では文字起こしモデル、整形モデル、よく使う文字起こし用の語句を
変更でき、整形モデルを空欄にすると文字起こし結果だけを記録します。**元の音声を保存** を
オンにすると、成功した録音の元音声もそのノートの添付ファイルとして保存されます。

音声ファイルと文字起こし結果はブラウザから OpenAI API へ直接送信され、アプリの運営
サーバーを経由しません。API キーはこの端末のブラウザの `localStorage` に平文で保存される
ため、個人の端末でのみ使用し、専用のプロジェクトキー・使用上限の設定・定期的な更新を
おすすめします。

### キーボードショートカット

ノート一覧では次のショートカットが使えます。入力欄で文字を入力している間は、一覧の
ショートカットは動作しません。`Ctrl/Cmd + R` はブラウザの再読み込みショートカットなので、
どこからでもアプリを再読み込みします。

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | ノート一覧を移動 |
| `Enter` | 現在のノートを開く · もう一度押すと編集 |
| `N` | 新しいノートを作成 |
| `` ` `` | リポジトリ選択を開く |
| `1`–`9` | 登録順にリポジトリを切り替え |
| `Esc` | 選択解除 · 削除の取り消し · 案内を閉じる |
| `Space` | 現在のノートを選択 |
| `Shift` + `↑` / `↓` | 複数ノートを範囲選択 |
| `Delete` / `Backspace` | 選択したノートをゴミ箱へ移動 |
| `Ctrl/Cmd + R` | アプリを再読み込み |

ノートを開いていて入力欄にフォーカスがないときは、次のショートカットも使えます。

| キー | 動作 |
| --- | --- |
| `T` | タグを追加 |
| `A` | ファイルを添付 |
| `P` | 上部固定の切り替え |
| `L` | ロック · ロック解除 |
| `Delete` | ノートをゴミ箱へ移動 |
| `G` | GitHub の Issue を表示 |
| `M` | MD ビューアを開く · 閉じる |
| `R` | アプリ全体を再読み込み |
| `S` | 現在のノートを保存 |

### PWA（インストール可能な Web アプリ）

本番ビルドは、ブラウザからインストールしてアプリのように使える PWA として動作します。
ブラウザでサービス URL を開き、ブラウザのインストールメニューを使ってください。
マニフェストと Service Worker は特定のドメインやホスティングサービスに依存せず、アプリが
配置されたパスを基準に動作します。Service Worker（ブラウザがアプリファイルを一時的に
保管する機能）はアプリと同一オリジンのファイルだけをキャッシュし、GitHub API へのリクエスト、
PAT、ノートデータはキャッシュしません。

### デスクトップアプリのダウンロード

macOS・Windows・Linux 向けのインストーラーは [GitHub Releases](https://github.com/zidell/ginote/releases)
からダウンロードできます。macOS は DMG、Windows 10/11 は MSI を使用します。新しい Windows
リリースは、SignPath Foundation による署名の設定が済み次第、署名済み MSI として公開されます。
デスクトップアプリは [note.gitools.net](https://note.gitools.net) を開くため、インターネット
接続が必要です。画面や一般的な機能の修正は Web デプロイで反映されます。

[Code signing policy](docs/CODE_SIGNING.md)

macOS の Homebrew インストール、ローカル実行、プラットフォーム別のパッケージングとリリース
手順は[デスクトップアプリのドキュメント](docs/DESKTOP.md)にまとめています。

## 運用・開発

Web アプリを変更するときは、ロックファイルに基づいて依存関係をインストールし、静的チェック・
テスト・本番ビルドをすべて通過させてからデプロイします。アプリは静的ファイルとしてデプロイ
され、デスクトップアプリのパッケージングと署名は Web デプロイとは別に管理します。データ
形式やセキュリティに影響する変更は、まず添付ファイルと暗号化のドキュメントを確認してください。
開発環境、検証コマンド、デプロイ・保守の手順は[開発・運用ドキュメント](docs/DEVELOPMENT.md)に
まとめています。
