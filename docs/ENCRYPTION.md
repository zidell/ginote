# 노트 잠금과 암호화 방식

이 문서는 Ginote 노트 잠금의 전체 동작과 저장 형식을 설명합니다. 잠금은 선택
기능이며, 일반 노트의 본문 상단 메뉴에서 **잠금**을 선택하면 6자리 숫자를
사용해 본문을 브라우저에서 암호화합니다. 암호화와 복호화는 브라우저의 Web
Crypto API에서 수행하며, 읽을 수 있는 본문과 잠금 숫자를 앱 운영 서버로
보내지 않습니다.

잠금이 적용된 이슈 본문은 GitHub에 암호문으로 저장됩니다. 잠금 노트를 해제한
상태에서 저장하는 댓글 본문도 같은 키와 형식으로 암호화됩니다. 제목 앞의 `🔒` 표식,
제목 자체, 라벨(태그), 첨부파일과 첨부파일 링크는 암호화하지 않습니다.

## 클라이언트 측 암호화 흐름

암호화 키와 평문은 브라우저 안에서만 사용합니다. GitHub API를 거치는 값은 잠금
노트의 경우 암호문입니다.

```text
브라우저: 평문 작성 ──(잠금 숫자 + pepper)──▶ 암호문 ──▶ GitHub 저장소
브라우저: 평문 표시 ◀─(잠금 숫자 + pepper)── 암호문 ◀── GitHub 저장소
```

앱 운영 서버는 노트 저장 API를 제공하지 않으므로 이 흐름에 참여하지 않습니다.

## 보호 경계

잠금은 GitHub 저장소에 저장되는 노트 본문과 잠금 노트를 해제한 상태에서 저장하는
댓글 본문을 클라이언트에서 암호화하는 추가 보호 기능입니다. GitHub에는 평문 대신
암호문이 전달되므로 저장소 데이터만 읽은 사람은 잠금 숫자 없이는 본문을 읽을 수
없습니다.

다음 정보는 잠금으로 숨겨지지 않습니다.

- 이슈 제목과 제목 앞의 `🔒` 표식
- GitHub 라벨(앱에서 사용하는 태그)
- 첨부파일과 이슈 본문에 들어간 첨부파일 링크
- 배포된 JavaScript와 Vite 번들에 포함된 배포 pepper

따라서 잠금은 강력한 비밀번호나 비밀번호 관리자를 대신하지 않습니다. 브라우저나
배포된 JavaScript가 변조된 경우, 또는 잠금 숫자가 노출된 경우에는 이 기능만으로
본문을 보호할 수 없습니다.

## 암호화 형식

1. 잠금 숫자는 정확히 6자리 숫자여야 합니다.
2. 키 재료는 배포별 pepper, 이슈 번호, 잠금 숫자를 결합해 만듭니다.
3. 키 재료를 PBKDF2-SHA-256으로 600,000회 반복해 256비트 AES 키를 파생합니다.
   암호화할 때마다 16바이트의 무작위 salt를 새로 사용합니다.
4. 본문은 12바이트의 무작위 IV를 사용하는 AES-GCM으로 암호화합니다. AES-GCM의
   인증 태그도 암호문에 포함됩니다.
5. 저장할 값은 `버전 바이트 + salt + IV + 암호문`을 이어 붙인 뒤 Base64로
   인코딩한 문자열입니다. 복호화에 필요한 salt와 IV는 이 값 안에 들어가지만,
   잠금 숫자와 pepper는 저장하지 않습니다.

현재 저장 형식 버전은 `2`입니다. 암호화 컨텍스트에 이슈 번호를 포함하므로,
다른 이슈의 암호문을 같은 숫자로 복호화할 수 없습니다.

## 잠금 세션

잠금 숫자는 저장하지 않고 앱이 실행되는 동안에만 세션 메모리에 기억합니다.
기본 기억 시간은 1시간이며, 환경설정에서 5분·15분·30분·1시간·3시간·8시간·
12시간·24시간 중에서 고를 수 있습니다. 세션이 만료되면 다시 6자리 숫자를
입력해야 합니다.

모든 잠금 노트에는 같은 숫자를 사용합니다. 잠금 숫자나 배포 pepper를 잊으면
기존 잠금 노트를 읽을 수 없습니다.

## 배포 pepper 설정

잠금 기능은 별도 환경변수 없이도 소스에 포함된 공개 기본값으로 동작합니다.
프로젝트를 포크해 직접 운영하거나 배포한다면, 첫 잠금 노트를 만들기 전에
배포마다 다른 pepper로 바꾸세요. pepper는 키 파생에 함께 넣는 배포별 값입니다.

한 번 생성합니다.

```bash
openssl rand -hex 32
```

생성된 64자리 값을 `.env.local`에 넣습니다.

```dotenv
VITE_NOTE_LOCK_PEPPER=생성한_64자리_값
```

`.env.local`은 Git에 커밋하지 마세요. Cloudflare Pages, Workers Builds,
GitHub Actions 등에서 빌드할 때는 같은 이름의 **빌드 환경변수** 또는 secret으로
넣어야 합니다. 외부에서 `npm run build`를 실행한 뒤 Workers Static Assets에
올리는 경우에는 빌드한 컴퓨터의 `.env` 또는 `.env.local` 값이 사용됩니다.
Worker를 실행할 때 넣는 변수는 이미 만들어진 Vite 번들에 반영되지 않습니다.

잠금 노트를 만든 뒤에는 모든 웹·데스크톱 빌드에서 같은 pepper를 계속 사용하세요.
배포 pepper를 바꾸거나 잃어버리면 6자리 숫자를 알고 있어도 기존 잠금 노트를
읽지 못할 수 있습니다.

이 환경변수는 Vite가 정적 JavaScript 파일 안에 넣으므로 서버 비밀처럼 숨겨지지
않습니다. 소스 저장소의 공통값 대신 배포마다 다른 암호화 재료를 쓰게 해 GitHub
이슈 본문만 유출된 경우에 추가 장벽을 제공하는 값입니다. 공개 호스팅의 빌드
결과를 볼 수 있는 공격자는 이 값을 분석할 수 있으므로, 6자리 잠금 숫자를
강력한 비밀번호나 비밀번호 관리자 대신 사용하지 마세요.
