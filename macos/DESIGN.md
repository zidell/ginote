# Ginote for macOS (Swift) 설계안

웹 앱(Svelte)의 기능을 모두 옮기는 macOS 전용 네이티브 앱의 설계다. **시험 프로젝트**다. 제품의
중심은 계속 Tauri 앱이고, 이 앱은 당분간 개발 Mac에서 로컬 빌드로만 돌린다. 릴리스·자동 업데이트·
Homebrew 배포·CI는 하지 않는다(§10). 화면 구성은 웹을 따르지 않고
macOS의 관례(분할 창, 메뉴바 명령, 툴바, 시트, 설정 창, Quick Look, 실행 취소)로 다시 짠다. 옮기는
것은 기능의 **의도**와 GitHub에 저장되는 **데이터 규약**이다. 데이터 규약은 한 글자도 바꾸지 않는다.

## 1. 목표와 범위

- **목표**: 맥에서 가볍게 쓰는 Ginote. WebView 없이 AppKit/SwiftUI만 쓴다.
- **완료 기준**:
  - 부록 A의 기능 대조표가 모두 채워진다.
  - 웹과 같은 저장소를 번갈아 써도 서로의 노트·잠금·첨부·댓글을 그대로 읽고 쓴다.
  - 메모리 목표: 저장소 하나, 노트 목록 30개, 노트 하나를 연 상태에서 `footprint` 기준 80MB 이하.
    목표치이고 아직 잰 값이 아니다. 구현 중 같은 조건으로 Tauri 앱과 나란히 잰다.
- **범위 밖**:
  - 웹·Tauri·모바일 앱. 그대로 유지한다.
  - Windows·Linux. Tauri 앱이 계속 맡는다.
  - 웹 빌드 교체(OTA)와 앱 업데이트. 로컬에서 다시 빌드해 쓴다.
  - 배포(서명·공증·릴리스·cask). 계속 쓸 만하다고 판단되면 그때 따로 설계한다.

## 2. 지켜야 할 데이터 규약 (웹과 공유)

아래는 이미 저장된 노트를 다시 읽는 규약이다. Swift 쪽 구현은 웹 구현과 같은 입력에 같은 출력을
내야 하고, 호환 테스트(§9)로 고정한다.

| 규약 | 웹 기준 위치 |
| --- | --- |
| 노트 = 열린 이슈, 휴지통 = 닫힌 이슈(30일), 태그 = 라벨, 고정 = 라벨 `ginote:pin`(화면에서 숨김) | `src/lib/github.js`, `pin-label.js` |
| 잠금: 제목 접두사 `🔒 `, 형식 v2(버전 1B + salt 16B + IV 12B + AES-GCM 암호문, Base64), 키 = PBKDF2-SHA256 600,000회(`pepper:이슈번호:PIN`) | `src/lib/note-lock.js`, `docs/ENCRYPTION.md` |
| 잠금 노트의 댓글도 같은 PIN·이슈 번호로 암호화 | `NoteEditor.svelte` |
| 첨부: `ginote-assets` 브랜치(orphan), `.issue-note-assets/issues/{N}/[comments/{C}/]{UUID}-{안전한 파일명}` | `github.js`, `docs/ATTACHMENTS.md` |
| 첨부 링크: 이미지는 `![](…/raw/ginote-assets/…)`, 그 밖은 `[](…)`, 본문 맨 위 `<!-- ginote:attachments:start/end -->` 관리 블록 | `attachments.js` |
| 편집 화면의 `{repo}/` 축약은 저장할 때 반드시 완전한 주소로 되돌린다 | `attachments.js` |
| 원본 음성 첨부: `voice-<ISO시각>.<확장자>`, 댓글에는 `<audio controls preload="metadata" src=…><a …>🎙 원본 음성 다운로드</a></audio>` | `voice-notes.js` |
| 전사 단어: `ginote-assets` 브랜치의 `.issue-note-assets/voice-hints.json`(`{version:1, hints}`) | `github.js` |
| 태그 색: NFC 이름의 `h = h*31 + 코드포인트` 해시 → HSL(h%360, 64%, 58%) | `colors.js` |
| 태그 정의 `이름: 설명`(이름 50자, 설명 100자, 코드포인트 기준), 새 이름은 앞 `#` 제거·공백→`-` | `tag-definition.js`, `notes.js` |
| 마감일: 본문 첫 줄 `due: YYYY-MM-DD` → D-n / D-DAY / D+n | `due-date.js` |
| 첫 줄 제목: 첫 줄을 다듬어 50자(코드포인트) | `notes.js` `automaticTitle` |
| 병합: 원본 본문은 시간순 `## YYYY-MM-DD HH:MM:SS @작성자` 섹션으로 본문에, 원본 댓글은 새 노트의 댓글로 시간순 재작성(빈 댓글 제외), 첨부를 새 이슈로 복사하고 URL 교체 | `note-merge.js`, `merge-notes.js` |
| 본문·댓글 길이 상한 58,982자(GitHub 65,536의 90%) | `github-limits.js` |
| 만료 첨부 정리: `closed:<30일 전` 이슈의 첨부 폴더만, 저장소마다 하루 한 번 | `attachment-prune.js` |

웹에서 이 규약을 바꿀 때는 Swift 쪽도 함께 고친다. 그래서 이 앱은 같은 저장소의 `macos/`에 두고,
웹 코드로 만든 기대값(fixture)을 Swift 테스트가 읽는다(§9).

## 3. 기술 선택

- **최소 macOS 14 (Sonoma)**: SwiftUI `@Observable`, `NavigationSplitView`, `Inspector`를 쓴다.
  Universal(arm64 + x86_64) 빌드.
- **UI**: 창 골격·목록·설정·시트는 SwiftUI. 편집기는 AppKit `NSTextView`를 `NSViewRepresentable`로
  감싼다.
  - 한글 조합, 선택, 드래그, 실행 취소, 맞춤법 메뉴, 찾기 막대는 OS 기본 동작을 그대로 쓴다.
  - 조합 중(`hasMarkedText()`)에는 텍스트 저장소를 건드리지 않는다. 문법 강조, 첫 줄 제목 계산,
    `{repo}/` 축약이 모두 해당한다. TUI를 포기한 원인이 바로 이 부분이므로 편집기 테스트에 넣는다.
- **네트워크**: `URLSession` + `async/await`로 GitHub REST API와 OpenAI API를 직접 부른다.
- **암호화**: `CryptoKit` AES-GCM, PBKDF2는 `CommonCrypto` `CCKeyDerivationPBKDF`.
- **자격 증명**: Keychain(`SecItem*`).
- **녹음**: `AVAudioRecorder`(AAC, `.m4a`). OpenAI 전사 API가 m4a를 받는다.
- **외부 패키지(SwiftPM)**: 둘만 쓴다.
  - [TOMLKit](https://github.com/LebJe/TOMLKit): `config.toml` 읽기·쓰기
  - [swift-markdown](https://github.com/swiftlang/swift-markdown): Markdown 보기 화면 파싱
- **프로젝트 파일**: [XcodeGen](https://github.com/yonaskolb/XcodeGen)의 `project.yml`을 커밋한다.
  `.xcodeproj`는 만들어 쓰고 커밋하지 않는다. 사람과 에이전트가 읽고 고치기 쉬운 텍스트 한 장으로
  프로젝트를 관리하려는 선택이다.

## 5. 화면 설계 (macOS 방식)

### 5.1 창 골격

창은 3단 `NavigationSplitView`다.

```text
┌──────────────┬──────────────────────┬────────────────────────────────┐
│ 사이드바      │ 노트 목록      [🎙][✎] │ 노트                             │
│              │ [🔍 검색 또는 #태그 ]  │ 툴바: 첨부·음성·태그·미리보기·잠금 │
│ 저장소        │ ── 고정됨 ──           │       ·고정·⋯                    │
│  ● 내 노트 ⌘1 │ D-3 회의 준비   🔒    │ (별도 제목 모드면) 제목             │
│  ○ 업무   ⌘2  │  첫 줄 요약…          │ #태그 #태그 [+]                   │
│ 보관함        │  #12 · 10월 3일       │ 첨부 썸네일 줄 ▢ ▢ ▢ [+]           │
│  노트         │ ── 노트 ──            │ 본문 (NSTextView, 최소 300pt)      │
│  휴지통(30일) │ …                    │ ───────────────                  │
│ 태그          │                      │ 작성자 · 날짜               ⋯     │
│  ● 업무       │                      │ 기록 본문 (🎙 재생 막대)            │
│              │                      │ [+ 기록 추가]        [🎙 음성 추가] │
│ 👤 zidell  ⚙ │                      │                                  │
└──────────────┴──────────────────────┴────────────────────────────────┘
창 부제목: "#12 · 수정 10:32 · 저장됨"
```

- **사이드바** (소스 목록 스타일):
  - 저장소 목록: 아바타, 표시 이름, `⌘1`–`⌘9`.
  - 보관함: 노트, 휴지통.
  - 태그 목록: 색 점, 이름. 누르면 태그로 거른다. 웹처럼 저장소 전체의 태그별 개수는 세지 않는다.
  - 웹의 "저장소 선택창"(`` ` ``)은 사이드바가 늘 보이므로 두지 않는다.
  - 적용 중인 저장소·보관함·태그 줄에는 ✓를 붙인다. ↑↓는 커서만 옮기고(저장소 줄 포함), ⏎나 클릭일 때만
    저장소를 바꾸거나 목록을 다시 읽는다. 화살표마다 GitHub를 다시 읽지 않게 하려는 것이다.
- **목록**:
  - 고정 노트는 "고정됨" 섹션으로 위에 둔다.
  - 끝에 닿으면 다음 페이지를 읽는다.
  - 행에는 마감 배지, 제목, 요약, `#번호 · 날짜`, 태그, 잠금·고정 아이콘이 들어간다. 각 항목은
    보기 메뉴와 설정에서 켜고 끈다.
  - 다중 선택은 OS 기본 동작이다: `⌘`클릭, `⇧`클릭, `⇧↑↓`, `⌘A`.
  - 키보드 커서와 열린 노트를 나눈다(웹과 같은 정책). ↑↓는 커서(목록 선택 강조)만 옮기고, ⏎로 연다.
    한 번 더 ⏎를 누르면 본문 맨 끝으로 포커스가 간다. 클릭은 바로 연다. 열린 노트는 왼쪽 강조색 막대로
    따로 표시한다.
  - 칸 이동: 목록에서 ←는 사이드바, →는 커서 노트를 열고 본문으로. 사이드바에서 →는 목록으로. 본문에서
    ⎋는 목록으로 돌아온다(본문 안의 ←→는 글자 이동이므로 쓰지 않는다).
  - 목록 맨 위에서 ↑는 검색칸 → 새 노트 버튼 → 음성으로 새 노트 버튼 순으로 올라가고, 그 위에서는 멈춘다
    (검색칸에 태그 후보가 떠 있으면 ↑↓는 후보를 고른다). 툴바 버튼에는 포커스 테두리를 그리고 ⏎·Space로
    누른다. ↓는 거꾸로 내려와 검색칸을 거쳐 목록으로, ⎋는 검색칸으로 돌아간다.
- **검색**: 목록 칸 맨 위의 검색칸(`NSSearchField`, `⇧⌘F`). 목록에 관한 것이라 목록 위에 둔다.
  - `#`을 치면 태그 후보가 뜨고 ↑↓·⏎로 고르면 태그 필터가 된다. 걸린 필터는 검색칸 아래 `#태그 ×` 칩으로 보인다.
  - 일반 글자는 GitHub hybrid 검색(최대 100개, 넘으면 안내)을 쓴다.
  - 휴지통에서도 같은 방식이다.
- **노트 창 따로 열기**: 목록에서 더블클릭하거나 "새 창에서 열기"(`⌥⏎`)를 고르면
  `WindowGroup(for: NoteID)` 창으로 열린다. 같은 노트가 두 창에 열려도 노트 세션 객체 하나를
  같이 써서 저장이 겹치지 않게 한다.

### 5.2 웹 → 맥 대응표

| 웹의 의도 | 맥 구현 |
| --- | --- |
| 토스트 알림 | 띄우지 않는다. 저장 상태는 창 부제목, 오류는 노트 위 경고 막대, 복사 등은 조용히 한다 |
| 확인 대화상자 | 창에 붙는 시트 경고(`.alert`/`.confirmationDialog`) |
| 노트 휴지통 이동 2초 대기 + 취소 | 웹과 같이 2초 대기, 행에 "삭제 중…"과 취소, ⎋로 취소. 옮긴 뒤에는 `⌘Z`로 복원(2026-10-05 사용자 결정) |
| 첨부 삭제 5초·댓글 삭제 3초 대기 + 취소 | 대기는 유지한다(되돌릴 수 없는 삭제). 대기 중에는 `⌘Z`와 항목의 "취소"로 막는다. 대기 목록은 디스크에 남겨 종료·충돌 뒤에도 이어서 처리한다 |
| 한 글자 단축키(N, T, A, P, L…) | 메뉴 명령과 `⌘` 조합 단축키(§5.4). 모든 명령이 메뉴에 있어 메뉴 검색으로도 찾을 수 있다 |
| 첨부 보기 모달 | Quick Look 패널(`QLPreviewPanel`). 썸네일에서 `Space`, `←→`로 넘긴다. Finder로 끌어내기 가능 |
| 첨부 추가 버튼·붙여넣기·끌어놓기 | 툴바 클립 버튼(열기 패널, 여러 개), 본문 붙여넣기, 창 어디든 끌어놓기 |
| 첨부 "Markdown 복사"·"본문삽입" | 썸네일 우클릭 메뉴 |
| MD 뷰어 | 보기 메뉴 "Markdown 미리보기" 토글. 스크롤 위치를 비율로 이어 준다 |
| 링크 위 말풍선 → 열기 | 본문의 링크를 밑줄로 표시하고 `⌘`클릭으로 연다. 우클릭 메뉴에 "링크 열기·복사" |
| 찾아 바꾸기(정규식) | 찾기는 OS 찾기 막대(`⌘F`). 바꾸기는 정규식 시트(`⌥⌘F`): `/패턴/플래그`, `$1`, 일치 개수와 예시, `{repo}/` 링크 보호 |
| 잠금 패널 | 시트. 숫자 6칸 보안 입력, 6번째 숫자에서 자동 제출 |
| 녹음 모달 | 시트. 파형, 일시정지, 완료(`⏎`), 닫기(`⎋`, 녹음이 있으면 확인) |
| 설정 오버레이 | 설정 창(`⌘,`) 탭: 일반·편집기·목록·저장소·태그·음성 |
| 시작 마법사 | 첫 실행 때 뜨는 단계형 창(마법사). 저장소 추가도 같은 화면을 시트로 쓴다 |
| 도움말 오버레이(보안·MCP·앱·단축키) | 도움말 메뉴 항목 → 도움말 창. "앱 설치" 주제는 맥 앱에는 맞지 않아 "정보(버전·설정 파일 위치)"로 바꾼다 |
| 테마 다크/라이트 | 시스템 따름(기본)·라이트·다크 |
| 언어 선택 | 앱 안에 두지 않는다. 시스템 설정 → 일반 → 언어 및 지역 → 앱별 언어가 그 역할이다 |
| 목록 폭 조절·저장 | 분할 창의 기본 동작(창 상태 자동 복원) |
| 창이 앞으로 오거나 온라인이 되면 새로고침(30초 간격) | 앱 활성화, 잠자기에서 깨어남, 네트워크 복구(`NWPathMonitor`) 때 같은 규칙 |
| 페이지를 떠날 때 keepalive 저장 | `applicationShouldTerminate`에서 남은 저장을 끝낸 뒤 종료(`.terminateLater`) |

### 5.3 편집기

- 본문은 `NSTextView`이고, Markdown 원문을 그대로 편집한다. 가벼운 문법 강조를 넣는다: 제목 크기,
  굵게·기울임, 코드 고정폭, 인용, 목록, 링크 밑줄. 조합 중에는 강조를 미룬다.
- **제목 방식**:
  - 첫 줄 모드: 제목 칸이 없고 첫 줄 50자가 제목이 된다.
  - 별도 모드: 위에 큰 제목 칸을 둔다(최대 256자).
- **편집 화면에서 숨기는 것**: 첨부 관리 블록은 편집 화면에서 빼고 저장 때 다시 만든다. 첨부
  주소는 `{repo}/`로 줄여 보여 준다. 웹과 같은 함수(`GinoteCore`)를 쓴다.
- **들여쓰기**: 여러 줄을 고른 채 `Tab`/`⇧Tab`을 누르면 줄마다 들여쓰거나 내어 쓴다. OS 실행 취소에
  잡히게 `shouldChangeText`를 거쳐 바꾼다.
- **글꼴·크기·폭**:
  - 글꼴은 시스템 글꼴 패널로 고른다. 설치된 모든 글꼴을 쓸 수 있다.
  - 웹의 내장 코딩 글꼴은 웹 전용으로 쪼갠 woff2라 쓰지 않는다. 필요하면 설치해서 고른다.
  - 크기, 줄 간격, 본문 최대 폭은 설정값을 따른다.
- **맞춤법·자동 고침**: 웹처럼 기본은 끈다. 편집 → 맞춤법 메뉴에서 켤 수 있다.
- **댓글(기록)**: 웹처럼 본문 바로 아래에 붙인다(사용자 결정, 2026-10-04). 본문 글 상자는 최소 300pt에서
  내용만큼 늘고, 구분선 아래로 시간순 기록, 맨 아래에 "기록 추가"·"음성 추가"가 있다. 본문과 기록이
  한 스크롤이다(`NoteDocumentView`: 글 상자 아래에 SwiftUI 기록 영역을 붙인 문서 뷰). 찾기 막대(`⌘F`)는
  이 스크롤 영역에 붙는다.
  - 미리보기 중에는 기록도 Markdown으로 그리고 추가 버튼을 숨긴다(웹과 같음).
  - 카드 메뉴: 음성 녹음 추가, 파일 첨부, 삭제.
  - 댓글 첨부는 기록 아래 이름 칩으로 보이고, 한 번 클릭하면 Quick Look으로 연다(본문 첨부도 같음, 웹과 같음).
  - `<audio>` 표기는 편집 화면에서 숨기고 재생 막대로 보여 준다. 저장할 때 다시 붙인다.
- **첨부 썸네일**: 인증된 다운로드로 받아 `~/Library/Caches/<번들 ID>/attachments/`에 저장한다. 파일의
  blob sha를 키로 쓰므로 내용이 바뀌면 새로 받는다. 이미지가 아니면 파일 아이콘과 이름을 보인다.
- **Markdown 미리보기**: swift-markdown으로 파싱해 `NSAttributedString`으로 그린다.
  - 제목, 목록, 체크박스(표시만), 인용, 코드, 표, 링크, 이미지(캐시에서)를 그린다.
  - HTML은 앱이 쓰는 `<audio>`만 "원본 음성" 표시로 바꾸고(재생은 기록의 재생 막대), 그 밖은 원문 그대로
    보인다. 웹은 정제한 HTML을 렌더링하지만, WebView를 쓰지 않는 대신 받아들이는 차이다.
  - 외부 이미지는 불러오지 않고 첨부(`ginote-assets`) 이미지만 그린다. 웹도 CSP로 GitHub 이미지만 허용한다.

### 5.5 설정 창 (`⌘,`)

| 탭 | 항목 |
| --- | --- |
| 일반 | 테마(시스템·라이트·다크), 자동 저장 대기(3–30초, 5), 목록 한 번에 읽는 수(10–100, 30), 저장소 목록 기억(5분–24시간, 60분), 잠금 숫자 기억(5분–24시간, 60분) |

웹처럼 "닫을 때 한꺼번에 반영"하지 않는다. 맥 설정 창 관례대로 바꾸는 즉시 반영한다. 웹이 닫을 때
하던 일은 각 값이 바뀔 때 한다: 목록 다시 읽기, 잠금 타이머 재시작, 전사 단어 저장.

## 6. 동작 설계

웹의 동작을 그대로 옮긴다. 주요 흐름만 적고, 세부 수치와 문구는 부록 A가 원본이다.

- **저장소 연결**:
  - `GET /user`와 `GET /repos/{repo}`로 확인한다.
  - 저장소 입력은 URL과 `owner/repo`를 모두 받는다.
  - PAT 생성 링크는 그 저장소 범위의 fine-grained 토큰 화면으로 연다(`makePatCreationUrl`).
- **목록**:
  - 열린 이슈는 `updated` 내림차순으로 페이지 단위로 읽는다. 첫 페이지에서만 search로 전체 개수를 센다.
  - 고정 노트는 `label:ginote:pin`을 따로 요청한다.
  - 휴지통은 search(`closed:>=30일 전`)를 `closed_at` 내림차순으로 정렬한다.
  - 오래된 응답은 요청 버전으로 버린다.
  - 재시도는 네트워크 오류와 5xx에만, 2·5·15초 간격으로 한다.
- **저장소별 목록 캐시**: 저장소 목록 기억 시간 동안 메모리에 둔다. 전환하면 즉시 보여 준 뒤 조용히
  새로고침한다.
- **새 노트**:
  - 로컬 자리표시를 만들고, 동시에 빈 이슈를 만들어 번호를 받는다. 지금 걸려 있는 태그 필터는 미리
    붙인다.
  - 번호가 오기 전에 쓴 글과 붙인 파일은 번호를 받은 뒤 저장·업로드한다.
  - 번호 받기에 실패하면 경고를 띄운다.
- **목록에서 붙여넣기**: 노트를 열지 않은 상태에서 붙여넣으면 그 글·파일로 새 노트를 만든다. 웹의
  전역 붙여넣기에 해당한다.
- **자동 저장**:
  - 입력이 멈추고 설정한 시간(기본 5초)이 지나면 저장한다.
  - 초안은 1초마다 디스크에 쓴다. 잠금 노트는 쓰지 않는다.
  - 바로 저장하는 때: 포커스를 잃을 때, `⌘S`, 태그 변경, 첨부, 잠금 전환, 휴지통 이동, 노트 전환,
    창 닫기, 앱 종료.
  - 마지막 저장본과 같으면 보내지 않는다. 저장 중에 또 쓰면 한 번 더 저장한다.
  - 실패하면 15초 뒤 다시 시도한다.
  - 제목이 비면 저장하지 않는다. 첨부만 있으면 "첨부 노트"를 제목으로 쓴다.
  - 없는 태그는 라벨을 먼저 만든다.
- **충돌**:
  - 저장 전에 이슈를 다시 읽는다. 다른 기기에서 휴지통으로 갔으면 "복원하고 저장할지" 묻고,
    아니오면 원격 내용을 불러온다.
  - PATCH 응답이 닫힘을 보여도 같은 질문을 한다.
  - 본문 병합은 하지 않는다. 나중에 쓴 쪽이 이긴다.
- **복구**: 앱이 갑자기 꺼져도 다음 실행 때 남은 작업을 이어서 처리한다. 대상은 초안, 댓글 초안,
  대기 중인 첨부 삭제다. 저장 위치는 §8이다.
- **잠금**:
  - 기억한 PIN이 있으면 잠글 때 바로 쓰고, 열 때 자동으로 시도한다. 실패한 PIN은 다시 쓰지 않는다.
  - 기억 시간이 지나면 저장할 것을 암호화해 저장한 뒤 다시 잠근다.
  - 잠긴 동안에는 본문, 제목, 태그, 첨부, 음성, 바꾸기, 미리보기, 댓글 편집을 막는다.
  - 맥에서 덧붙이는 동작: 화면 잠금과 잠자기 때 기억한 PIN을 지운다. 설정으로 끌 수 있게 하고,
    기본값은 켬이다.
- **첨부**:
  - 노트당 30개(본문과 댓글 합계), 파일당 10MB까지 받는다. 한 번에 한 묶음씩 차례로 올린다.
  - 노트를 열면 이슈 폴더를 확인한다. 연결된 첨부를 먼저 보이고, 본문에 링크가 없는 고아 첨부도
    계속 보인다.
  - 댓글 첨부는 댓글을 먼저 저장해야 붙일 수 있다.
  - 삭제 순서: 본문 링크를 지우고 저장한 다음 파일을 지운다. 404는 성공으로 본다.
- **댓글**:
  - 만들기, 고치기, 지우기(3초 대기). 빈 새 댓글은 버린다.
  - 댓글을 지우면 그 댓글만 쓰던 첨부도 지운다.
  - 잠금 노트의 댓글은 암호화한다.
- **태그**:
  - 노트 태그 선택기: 최대 12개 후보, `이름: 설명`으로 새로 만들기.
  - 이름 바꾸기·삭제는 저장소 전체에 적용하고, 열린 노트와 초안의 태그도 함께 고친다.
- **고정**: 화면을 먼저 바꾸고, 실패하면 되돌린다. `ginote:pin` 라벨이 없으면 만든다.
- **다중 선택**:
  - 할 수 있는 일: 태그 일괄 적용(모두 붙어 있으면 떼고, 아니면 붙인다), 병합(열린 노트 2개 이상),
    휴지통 이동·복원.
  - 선택 중 넓은 창에서는 누른 노트를 읽기 전용으로 미리 본다.
- **병합**:
  - 원본을 다시 읽고 임시 이슈를 만든 뒤 첨부를 복사하고 시간순 본문을 쓴다. 원본 댓글은 본문에 넣지 않고
    새 노트의 댓글로 시간순으로 다시 남긴다(본문 아래 기록으로 보인다). 그다음 원본을 닫는다.
  - 실패하면 임시 이슈를 닫고 원본은 그대로 둔다.
  - 진행 중에는 창을 막는 시트를 띄운다.
- **음성**:
  - 녹음은 최대 60분이다. 시작음을 내고, 일시정지할 수 있다.
  - 처리 순서: 전사(언어 힌트, 전사 단어) → 정제(고정 시스템 프롬프트, 사용자 규칙, 기존 태그,
    JSON 스키마). 각 단계는 한 번 재시도한다.
  - 보낼 곳:
    - 새 노트: 제안 제목을 쓴다.
    - 본문 끝, 새 댓글, 기존 댓글 끝: 제안 제목은 쓰지 않는다.
  - 원본 음성 보존을 켜면 녹음 파일(`.m4a`)을 이슈 폴더에 올린다. 댓글로 보낼 때도 이슈 폴더에 두고
    댓글 본문에 `<audio>` 표기만 붙인다(웹과 같음).
  - 실패하면 원본 음성을 내려받을 수 있게 한다. API 키가 없으면 설정의 음성 탭을 연다.
- **만료 첨부 정리**: 연결할 때 저장소마다 하루 한 번 백그라운드에서 돌린다. 열려 있는 노트는
  건너뛴다.
- **앱 업데이트**: 하지 않는다(로컬 빌드). 웹의 앱 업데이트 설정·창은 옮기지 않는다.

## 7. 잠금 pepper

웹(`src/lib/note-lock.js`)과 같은 규칙이다: **값이 있으면 그 값, 없으면 소스의 기본값**.

- **기본값**: `GinoteCore/Lock/NoteLock.swift`의 상수다. 웹 `DEFAULT_APP_PEPPER`와 같은 문자열이고,
  호환 테스트가 웹에서 만든 기본값 암호문을 풀어 두 값이 같은지 확인한다.
- **로컬 빌드**: Xcode 빌드 단계가 `macos/scripts/lock-pepper.sh`를 실행해
  `Ginote/Generated/LockPepper.swift`를 만든다. 이 파일은 커밋하지 않는다.
  - 값을 찾는 순서는 Vite 프로덕션 빌드와 같다: 빌드 환경변수 `VITE_NOTE_LOCK_PEPPER` → 저장소 루트의
    `.env.production.local` → `.env.production` → `.env.local` → `.env`.
  - 그래서 이 저장소의 `.env`에 있는 값을 그대로 쓴다.
  - 어디에도 없으면 빈 값을 쓰고, 앱은 기본값을 쓴다.
  - 스크립트는 값을 출력하지 않는다. 생성 파일에는 Base64로 넣어 문자열 이스케이프 문제를 피한다.
- **배포 빌드**: 지금은 없다. 나중에 배포한다면 웹 배포(`ci.yml`)·데스크톱 릴리스(`release.yml`)와
  같이 GitHub Actions 저장소 변수 `VITE_NOTE_LOCK_PEPPER`를 빌드 환경변수로 넘긴다.
- **복호화 순서**: 설정된 pepper로 먼저 열고, 실패하면 기본값으로 다시 연다(웹과 같음).
  암호화는 설정된 pepper로만 한다.

## 8. 설정 파일·자격 증명·로컬 상태

- **이름과 번들 ID**: 앱 이름 `Ginote Native`, 번들 ID `net.gitools.note.mac`. Tauri 앱
  (`Ginote.app`, `net.gitools.note`)과 같은 Mac에서 함께 돌려도 앱·설정·자격 증명이 겹치지 않게 따로 둔다.
  빌드 결과는 `/Applications`에 넣지 않고 빌드 폴더에서 바로 실행해도 된다.
- **설정 파일**: `~/Library/Application Support/net.gitools.note.mac/config.toml`.
  - [Agent Configuration Accessibility](https://github.com/zidell/agent-configuration-accessibility)
    원칙을 그대로 따른다. 키마다 주석(뜻·허용값·기본값·적용 시점)을 달고, 앱이 저장할 때 전체를 다시
    쓰며, 1초 안에 바깥 수정을 반영하고, 결과를 같은 폴더의 `config-status.txt`에 남긴다. 문법
    오류가 나면 파일 전체를 무시한다.
  - 키 이름은 웹 스키마(`src/lib/app-config.js`)를 따른다. 맥에서 뜻이 없는 키는 뺀다:
    `display.language`, `display.sidebar_width`, `display.editor_font`의 웹 글꼴 값.
  - 맥 전용 키를 더한다: `display.theme`의 `"system"`, `behavior.clear_lock_on_sleep`.
    Tauri 앱과 파일을 나누는 이유가 이것이다. Tauri의 스키마 검사가 이 키들을 버리지 않게 하려는 것이다.
- **명령줄**: `Ginote.app/Contents/MacOS/Ginote --config-path`와 `--help`를 지원한다.
  `Contents/Resources/readme.txt`에 설정 위치·적용·자격 증명을 적는다.
- **자격 증명**: Keychain, 서비스 `net.gitools.note.mac`. 이름은 `github-pat:<워크스페이스 id>`와
  `openai-api-key`(웹과 같은 이름 규칙)다.
- **처음 실행 때 가져오기**: 내 설정 파일이 없고 Tauri 앱의 `config.toml`이 있으면 가져온다.
  - 가져오는 것: 워크스페이스, 표시·동작·음성 설정.
  - 자격 증명은 Tauri의 Keychain 항목(서비스 `net.gitools.note`)에서 읽어 내 항목으로 복사한다.
    macOS가 처음 한 번 접근 허용을 묻는다.
  - 원본은 건드리지 않는다.
- **로컬 상태** (설정이 아니다):
  - 위치: `~/Library/Application Support/net.gitools.note.mac/state/`의 JSON 파일.
  - 내용: 초안, 대기 작업(댓글 초안·첨부 삭제), 첨부 정리 시각, OpenAI 모델 목록 캐시, 아직 못 올린
    전사 단어.
  - 웹의 `localStorage` 키와 같은 구조를 쓴다.

## 9. 테스트와 웹 호환 검증

- **`GinoteCore` 단위 테스트** (`swift test`): 웹의 `*.test.js`가 다루는 순수 로직을 같은 사례로
  옮긴다. 대상은 제목, 평문, 마감일, 태그 정의·색, 링크 파싱·관리 블록·축약, 병합 본문, 설정 파싱·
  렌더링, 정제 결과 파싱이다.
- **웹 호환 fixture**: `macos/scripts/make-fixtures.mjs`가 웹 모듈(`src/lib/*.js`)을 직접 불러 기대값을
  만든다. 결과는 `Tests/GinoteCoreTests/Fixtures/*.json`에 커밋한다.
  - 잠금: 웹에서 만든 암호문(정해진 PIN·이슈 번호, 기본값과 시험용 pepper)을 Swift가 푼다. 반대로
    Swift가 만든 암호문은 테스트 안에서 Node로 넘겨 웹 코드가 푼다(Node가 있는 환경에서만 실행).
  - 첨부·태그·병합: 같은 입력에 대한 웹 출력과 Swift 출력이 글자까지 같아야 한다.
  - 웹 쪽 규약 코드가 바뀌면 fixture를 다시 만든다. CI가 없으므로 `swift test`가 fixture와 웹 코드가
    어긋났는지도 확인한다(Node가 있으면 fixture를 다시 만들어 비교).
- **GitHub 가짜 서버**: `URLProtocol` 가짜로 GitHub API를 메모리 저장소로 바꿔 흐름을 시험한다.
  저장, 충돌, 새 노트 번호, 첨부, 병합, 정리가 대상이다. `src/App.test.js`의 방식과 같다.
- **편집기**: XCUITest로 한글 조합을 시험한다. 조합 중 엔터, 마지막 글자 뒤 줄바꿈, 조합 중 자동
  저장 시점이 대상이다.
- **메모리**: 단계마다 §1 조건에서 `footprint`로 재고 결과를 README에 적는다.

## 10. 빌드와 실행 (로컬 전용)

- **빌드**: `brew install xcodegen` → `cd macos && xcodegen` → Xcode에서 실행하거나 `xcodebuild`로
  빌드한다. 서명은 로컬 개발 서명(Sign to Run Locally)으로 충분하다. 절차는 `macos/README.md`에 적는다.
- **검사**: `cd macos/Packages/GinoteCore && swift test`. CI에는 넣지 않는다. 웹 쪽 검사
  (`npm run check`, `npm test`, `npm run build`, `cargo test`)와 GitHub Actions는 이 폴더와 상관없이
  지금처럼 돈다.
- **기존 배포에 영향 없음**: `macos/`는 웹 빌드(Vite), Tauri 빌드, 릴리스 워크플로 어디에도 들어가지
  않는다. `release.yml`의 경로 조건(`src-tauri/**` 등)에도 걸리지 않으므로 push해도 데스크톱 릴리스가
  생기지 않는다.
- **나중에 배포를 정한다면** 따로 설계한다. 그때 확인할 점:
  - Tauri 업데이터가 보는 `releases/latest`를 가져가지 않게 올리기
  - `release.yml`의 "최신 20개만 남기기"가 다른 태그를 지우지 않게 하기
  - 서명·공증, 업데이트 방식, Homebrew cask 이름

## 부록 B. 웹 대조 점검 기록

웹 컴포넌트와 테스트를 기준으로 맥 코드를 다시 대조해 고친 차이다. 같은 종류를 다시 놓치지 않도록 남긴다.

**2026-10-04** (24건)

- **저장 기준값:** 고정·일괄 태그가 저장 기준값을 지금 본문으로 바꿔, 저장 안 된 수정이 "저장됨"이 되던 것.
  이제 기준값은 GitHub에 있는 제목·본문·태그(`lastRemoteNote`)이고, 태그만 바뀌면 태그만 고친다.
- **새 노트 제목:** 새 노트 제목이 비어 시작해 제목을 따로 쓰는 모드에서 저장이 멈추던 것. 웹처럼 "새 노트"로 시작한다.
- **노트 열기:** 예전에 열어 둔 세션이 옛 본문을 보이고 덮어쓰던 것. 웹처럼 열 때마다 이슈를 다시 읽는다.
- **번호 받기 실패:** 번호를 받지 못한 새 노트가 버려지던 것. 저장할 때 이슈를 만들고, `⌘N`은 그 노트를 다시 시도한다.
- **잠금 숫자:** 자동으로 시도한 숫자가 틀리면 기억한 숫자가 지워지던 것. 실패 기록은 노트별로 둔다.
- **목록·검색 상태:**
  - 목록이 다시 읽혀도 열어 둔 노트를 닫지 않는다.
  - 고정 노트는 검색·태그 필터 중에도 맨 위에 보인다.
  - 노트/휴지통 전환·태그 필터·새 노트는 검색어를 지운다. 빈 검색 제출은 태그 필터를 푼다.
  - 태그 후보를 고르지 않은 ⏎는 일반 검색이고, 후보 사이 ↑↓는 순환한다.
  - 목록 제목의 Markdown 기호를 걷어낸다.
- **연결:** 연결하지 못한 상태의 "다시 시도"는 다시 연결한다.
- **기록(댓글):**
  - 본문 blur 때 막 추가한 빈 기록 카드가 사라지지 않는다.
  - 미리보기 중에는 기록도 Markdown으로 보인다.
  - 앱이 꺼진 뒤 복구하는 새 기록 초안이 음성 표기를 포함한다.
- **여러 개 선택:** 미리보기를 첨부·기록까지 담은 읽기 전용 노트로 보인다.
- **편집기:** 한 줄 일부를 골라도 Tab이 줄 단위로 들여쓴다.
- **태그 선택기:** 저장소 목록에 없는 노트 태그도 보여 뗄 수 있다.
- **붙여넣기·끌어놓기:**
  - 노트를 열어 둔 채 목록에서 붙여넣으면 새 노트를 만들지 않는다.
  - 노트 영역 어디에 끌어놓아도 첨부한다.
- **휴지통:** 옮기기 전에 대기 중인 첨부 삭제를 끝낸다.
- **음성:**
  - 키 없이 녹음을 누르고 설정에서 키를 넣으면, 설정을 닫을 때 녹음을 이어서 연다.
  - 목록 툴바에 음성 새 노트 버튼을 둔다.
- **저장소 전환:** 저장소를 다시 고르면 30초 제한 없이 조용히 새로 읽는다.
- **병합(웹도 함께 변경):** 원본 댓글을 본문에 넣지 않고 새 노트의 댓글로 옮긴다.

  항목부터 하나씩 취소, 보내는 중인 항목은 취소 불가, 저장소를 바꾸면 대기 중인 것을 모두 취소. 열린 노트에도
  "삭제 중…" 덮개와 취소가 보인다.
- 잠금 노트(잠김·열림)는 머리 띠를 황금빛으로 칠하고(웹 `.detail-toolbar.is-lock-protected`), 본문 배경에도
  같은 빛을 섞고, 툴바 잠금 아이콘을 경고색으로 둔다.
- 본문 편집 중(포커스)에는 노트 칸 배경을 편집 배경색으로 바꿔 읽기와 구분한다.
- 잠금 숫자 입력칸은 포커스 동안 로마자 입력기만 허용한다(한글 입력기에서도 숫자가 쳐진다).
